# Migrating from v0.8.x to v1.0.0
{: .no_toc }

This guide covers breaking public API renames and naming changes in MSR Core v1.0.0.
{: .fs-6 .fw-300 }

{: .no_toc .text-delta }

## What changed

The core class and its public option and dependency types now use the `Runner` name:

| Before (v0.8.x) | After (v1.0.0) |
| --- | --- |
| `MigrationScriptExecutor` | `MigrationScriptRunner` |
| `IExecutorOptions` | `IRunnerOptions` |
| `IMigrationExecutorDependencies` | `IRunnerDependencies` |
| `ILockingService` | `ILockingProvider` |
| `ITransactionManager` | `ITransactionProvider` |
| `DefaultTransactionManager` | `DefaultTransactionProvider` |
| `CallbackTransactionManager` | `CallbackTransactionProvider` |
| `BackupService` / `IBackupService` | `BackupOrchestrator` / `IBackupOrchestrator` |
| `SchemaVersionService` / `ISchemaVersionService` | `SchemaVersionOrchestrator` / `ISchemaVersionOrchestrator` |
| Handler `lockingService` / `transactionManager` | Handler `lockingProvider` / `transactionProvider` |
| Runner options `backupService` / `schemaVersionService` | `backupOrchestrator` / `schemaVersionOrchestrator` |
| No lock orchestration interface | `ILockingOrchestrator` contract |
| CLI factory callback | `createExecutor` → `createRunner` |
| Lock owner identifier and storage column | `executorId` / `executor_id` → `runnerId` / `runner_id` |

There are no backward-compatible aliases. Update imports, base classes, constructor and factory signatures, and type references together. Database-specific implementation classes should follow the `<Database>Runner` naming convention, such as `FirebaseRunner` or `PostgresRunner`; see the [CLI adapter development guide](../guides/cli-adapter-development).

## Migration steps

### 1. Upgrade the package

```bash
npm install @migration-script-runner/core@^1.0.0
```

### 2. Update imports and inheritance

```typescript
// Before (v0.8.x)
import {
  MigrationScriptExecutor,
  IExecutorOptions,
  IMigrationExecutorDependencies
} from '@migration-script-runner/core';

export class FirebaseAdapter extends MigrationScriptExecutor<IFirebaseDB, FirebaseHandler> {
  private constructor(dependencies: IMigrationExecutorDependencies<IFirebaseDB, FirebaseHandler>) {
    super(dependencies);
  }

  static getInstance(options: IExecutorOptions<IFirebaseDB>): Promise<FirebaseAdapter> {
    // Create the handler and return the adapter.
  }
}
```

```typescript
// After (v1.0.0)
import {
  MigrationScriptRunner,
  IRunnerOptions,
  IRunnerDependencies
} from '@migration-script-runner/core';

export class FirebaseRunner extends MigrationScriptRunner<IFirebaseDB, FirebaseHandler> {
  private constructor(dependencies: IRunnerDependencies<IFirebaseDB, FirebaseHandler>) {
    super(dependencies);
  }

  static getInstance(options: IRunnerOptions<IFirebaseDB>): Promise<FirebaseRunner> {
    // Create the handler and return the runner.
  }
}
```

Adapt the return type and factory body to your actual initialization pattern. If the adapter class is imported by consumers, renaming it to `<Database>Runner` is a source-level breaking change for those consumers as well.

### 3. Rename the CLI factory callback

Rename the `createExecutor` property to `createRunner`, including the callback passed to `extendCLI`. The v1.0.0 API does not provide a `createExecutor` compatibility alias.

```typescript
// Before (v0.8.x)
const oldProgram = createCLI<IFirebaseDB, FirebaseRunner>({
  createExecutor: async (config) => FirebaseRunner.getInstance({ config }),
  extendCLI: async (program, createExecutor) => {
    const runner = await createExecutor();
  }
});
```

```typescript
// After (v1.0.0)
const program = createCLI<IFirebaseDB, FirebaseRunner>({
  createRunner: async (config) => FirebaseRunner.getInstance({ config }),
  extendCLI: async (program, createRunner) => {
    const runner = await createRunner();
  }
});
```

### 4. Rename lock owner identifiers

Update locking provider methods and lock hook callbacks from `executorId` to `runnerId`. If your locking provider stores the identifier in a database column named `executor_id`, rename that column to `runner_id` and update its queries. Adapt the table name and SQL syntax to your database. Complete this migration while old application instances are stopped so old and new instances do not coordinate through different lock columns.

For example, in PostgreSQL:

```sql
ALTER TABLE migration_locks RENAME COLUMN executor_id TO runner_id;
```

### 5. Update provider and orchestrator APIs

Database adapters now provide locking and transaction capabilities through provider contracts. Rename implementations and handler properties:

```typescript
// Before (v0.8.x)
class PostgreSqlLockingService implements ILockingService<PostgreSqlDB> {
  // database-specific lock operations
}

const handler = {
  lockingService: new PostgreSqlLockingService(db),
  transactionManager: new CustomTransactionManager(db)
};
```

```typescript
// After (v1.0.0)
class PostgreSqlLockingProvider implements ILockingProvider<PostgreSqlDB> {
  // database-specific lock operations
}

const handler = {
  lockingProvider: new PostgreSqlLockingProvider(db),
  transactionProvider: new CustomTransactionProvider(db)
};
```

MSR orchestration types also use explicit names:

- `BackupService` / `IBackupService` become `BackupOrchestrator` / `IBackupOrchestrator`.
- `SchemaVersionService` / `ISchemaVersionService` become `SchemaVersionOrchestrator` / `ISchemaVersionOrchestrator`.
- `LockingOrchestrator` now implements the exported `ILockingOrchestrator` contract.
- Built-in transaction implementations become `DefaultTransactionProvider` and `CallbackTransactionProvider`.
- `IRunnerOptions` properties `backupService` and `schemaVersionService` become `backupOrchestrator` and `schemaVersionOrchestrator`.

Rename direct imports, custom implementation types, and property names together. The built-in class renames are breaking for consumers that instantiate these classes directly.

### 6. Search for old names

Search your source, tests, locking-provider implementations, and current documentation for renamed API symbols and properties, then update each remaining reference. Historical release notes may retain old names where they describe the API that existed in that release.

## Verification

After updating the adapter:

1. Run the TypeScript build and your test suite.
2. Confirm public imports resolve from `@migration-script-runner/core`.
3. Search for old API symbols, `createExecutor`, `executorId`, and `executor_id` in current source and examples.
4. Confirm your CLI factory uses `createRunner` and your locking implementation uses `runnerId` / `runner_id`.
